# Подготовка сайта к публикации

Проект можно запускать локально через `python app.py` и публиковать на любом
Linux-хостинге, который поддерживает Python и команду запуска Gunicorn.

## Что уже готово

- Отладочный режим по умолчанию выключен.
- Добавлена production-команда `gunicorn app:app`.
- Добавлен адрес `/health` для проверки доступности сайта.
- Статические файлы кэшируются браузером на 30 дней.
- Добавлены базовые защитные HTTP-заголовки.
- Добавлены Open Graph-метаданные для аккуратной ссылки в социальных сетях.
- Локальные заявки не попадают в Git благодаря `.gitignore`.

## Локальный запуск

```powershell
python -m pip install -r requirements.txt
python app.py
```

После запуска откройте `http://127.0.0.1:5000`.

## Команда для хостинга

```text
gunicorn --bind 0.0.0.0:$PORT app:app
```

Та же команда уже записана в `Procfile`. Большинство Python-хостингов
подставляют переменную `PORT` автоматически.

## Переменные окружения

| Переменная | Значение | Обязательность |
| --- | --- | --- |
| `PORT` | Порт, выданный хостингом | Обычно задаёт хостинг |
| `HOST` | `0.0.0.0` для внешнего доступа | Только для `python app.py` |
| `FLASK_DEBUG` | `0` | Рекомендуется |
| `REQUESTS_FILE` | Постоянный путь к CSV | Если нужно сохранять заявки |

Пример находится в `.env.example`.

## Важно о форме заявок

Сейчас форма сохраняет данные в CSV-файл. На хостинге с временной файловой
системой записи могут исчезнуть после перезапуска. Для первого запуска можно
подключить постоянный диск и задать `REQUESTS_FILE`, например:

```text
/var/data/requests.csv
```

Перед активным продвижением лучше подключить почту, CRM или базу данных. Не
публикуйте сайт с обещанием надёжного хранения заявок, пока постоянное хранилище
не настроено.

## Финальная проверка перед публикацией

1. Выбрать хостинг и домен.
2. Настроить постоянное хранение заявок или заменить CSV на почту/CRM.
3. Указать production-команду из этого файла.
4. Проверить `/health`: ответ должен быть `{"status":"ok"}`.
5. Отправить тестовую заявку без реальных персональных и рабочих данных.
6. Проверить мобильную версию и ссылку на сайт в мессенджере.
